# Gstack delivery through merge
1. Scoped evidence reaches existing read-only workers
   - the frozen graph-context candidate's runtime subset (graph_context.py, task_graph.py integration, their tests, the task-graph contract) lands with the materialize(packet, node) and verify(handoff, packet=None, node=None) interfaces and CLI behaviour unchanged; pilot wrappers and transcripts stay non-runtime
   - refusal tests cover stale attested source, refreshed revision with stale content, moved prerequisite with unchanged consumer pointer binding, ambiguous repository selection, and selected or unselected attested tampering; each asserts zero workers and no run directory; empty-selection semantics and untrusted-content labels are retained
   - the context and task-graph test files run through their discovered entry points with explicit counts printed to stdout and exit 0; a reproduced intermittent failure is kept as unresolved evidence, with no retry and no weakened assertion
2. Persist progress and refresh evidence within bounded recovery
   - goal_delivery.next_action(delivery, observed) returns one allowed phase or action, or a specific blocked or pending state, from the original approval reference, candidate and base, source bindings, checkouts, attempt counts and verified external observations
   - goal_delivery.reserve_review(delivery, change_id, review_id) updates the change's cumulative attempt record or refuses; a replacement review ID never creates a fresh change budget; a restart preserves prior attempts and elapsed active time; concurrent ownership acquisition has one winner
   - peer_review.apply_ledger_runs(packet, specs) parses REPO=RUN_ID, and `round` and `dispatch` accept --ledger-run; a refreshed round reports the new head with head_matches true and receipt_verified true; a wrong-head, wrong-repository or tampered receipt is not verified; the retained packet and earlier round bytes are unchanged; relative repository paths survive background dispatch
   - goal_run.resume(goal_id, get, repo_name) loads persisted state, re-observes GitHub and local prerequisites, saves validated progress and returns the next supervisor action; no model-supplied declaration establishes that a merge or approval occurred; an unknown or unreadable budget or authority blocks further action
   - the new and changed tests fail before the functions change and pass after; test_goal_delivery.py, the goal-run tests and the ledger and path tests run through their existing runners with counts printed and exit 0
3. Finish delivery, recover a missing release record, and synchronize
   - goal_delivery.sync_checkout(checkout, merge_sha) returns synced with observed identity, SHA, status and time, or sync_pending with the named checkout and reason; host mismatch, dirt, unexpected branch, divergence or an unavailable path causes no checkout mutation; a clean eligible checkout is fast-forwarded only
   - goal_delivery.delivery_status(delivery) is complete only after every required merge, release record, release companion and named checkout is confirmed, otherwise the applicable phase, blocker or sync_pending
   - a subprocess-level test shows a fixture GitHub accepting the exact-head merge, the process exiting before record-release, and a fresh process discovering the merge, recording it once and synchronizing the required clean checkout: one accepted merge, zero merge requests on resume, one release record, outcome complete; the dirty variant keeps tracked and untracked hashes, status and Git metadata identical and reports sync_pending; wrong-host, unavailable, unexpected-branch, divergent and main-advanced-containing-the-merge cases are covered, as are a moved PR head refusing merge, a lost merge response discovered remotely, a missing release companion preventing completion, an owner gate still blocking, and failure after record creation resuming idempotently
   - goal_run.complete records the verified goal merge without ending delivery before release and sync obligations; historical goal records are not rewritten; record renders merge, record and sync states separately; command contracts drive the allowed actions automatically, launch the receiving session from shared durable state, and keep the command-node transport labelled experimental
   - the focused suites and the repository's full runner pass once on the candidate; version_bump.py runs in its applicable mode before final review; check_ledger.py run records the head-bound test receipt; versions move exactly as the release mode requires, with the marketplace top-level bump left to the goal's declared release companion
