I checked each candidate against the plan text and found no contradictions, only five ambiguities.

**Dropped after re-reading**
- **MR-006.3 vs MR-006.7:** these don't conflict. MR-006.7 merges the lines that exist at the time of that one manual run. MR-006.3 says lines written to an old location while the variable is unset are not merged later. The two apply to different lines.
- **My earlier A3 (the `history: "unset"` field):** the plan says "The refusal record gains one field of its own", and the boundary constraint exempts "a field an item adds to its own record". The plan's own wording puts the field on the exempt side.
- **My earlier A4 (brief pull request vs `goal-envelope`):** the plan names "the goal's brief pull request" and "a goal's pull request into `main`" as separate things. It never says the brief pull request targets `main`.
- **My earlier C1:** I downgraded it to an ambiguity. Shadow mode and non-gate subcommands can satisfy MR-006.1 and MR-006.6, because only route and quorum mode refuse. What the text doesn't settle is whether a gate in route or quorum mode still uses the old location when the variable is unset.

**Ambiguities kept**
- **MR-006.1 and MR-006.6 vs MR-006.3:** "Old location is used when unset" is tested for all five resolvers, but MR-006.3 says gates refuse and "no gate reads" the old location. It's undecided whether the gate resolvers are exempt.
- **MR-006.3 alone:** "is unset and runs in shadow" can be read two ways. It is also unclear which entry points of `model_select.mjs` and `decider_council.py` count as writers, which "never refuse".
- **MR-006.2 vs MR-006.1:** "both now sit under the same root" holds only when the variable is set. With it unset, each resolver falls back to its own old location.
- **MR-006.7 and the *Links introduced* paragraph vs *Transcript-derived data isn't readable outside the executing principal…*:**
  - MR-006.7 copies ledger lines into a directory that "the Projects repository tracks".
  - The plan doesn't say whether the decisions or model-routing lines are built from session files. If they are, the publish gate applies before they are merged.
- **MR-006.8:** the plan says the pull request "that carries MR-006 and XE-047 (CI-002)", but it states neither XE-047 nor CI-002. It can't be decided from the text whether the two share one pull request or what the single top-level version bump depends on.
