I called the advisor. It confirmed the contradiction (C1) and A1–A4, and it told me to fix the ids on A5. It also suggested candidates, which I checked against the text. Two survive as A6 and A7, and a third is folded into A4. I dropped the "never below 1" candidate because I couldn't state a clean scenario for it. **Contradiction**
- **C1, GO-023.2 against GO-023.3 (GO-023.4 supports):** after a host refusal during a retest, the two criteria give different ceilings.
  - Criterion 2 says the approved retest ceiling stands in for the host limit "until the run ends or a refusal comes".
  - Criterion 3 says `tick` and `launch-check` use the retest ceiling "while a verified retest is running".
  - After a mid-retest refusal the retest is still running, so criterion 3 keeps the high ceiling. Criteria 2 and 4 say the lowered limit governs.

**Ambiguities**
- **A1, GO-023.8 (hard-cap bullet):** `goal_run.py start` is said to "refuse all three markers" and also to refuse "unless the run uses a runner that checks the remaining spend". It's unclear whether `start` can ever run a hard-cap goal.
- **A2, GO-023.8 (successor bullet) against the constraint "A goal delegates item selection, not authority":** the constraint holds a successor to the root brief byte for byte. Criterion 8 copies `DEPS.json` from the immediate predecessor and lets it differ for items the revised `PLAN.md` adds or removes. The plan doesn't say whether `PLAN.md` or `DEPS.json` is part of the brief.
- **A3, GO-023.3 against GO-023.4:** the "30 claims, refusal at the 15th launch" test expects claims 16–30 to be "not yet launched". Criterion 4 says that if every claim in one message was sent, none is "not yet launched". The test doesn't say whether the claims went out in one message or one at a time.
- **A4, GO-023 Links, GO-023.2, GO-023.4 and GO-023.10:** the host record is shared by every run on the host, but "running" is counted per run. The plan doesn't say which count sets the new limit. Parallel test-drafting agents under criterion 10 use host capacity while "holding no worker slot", so they sit outside the count too.
- **A5, GO-023.5 with GO-023.4 and Links:** an approval must name `current limit <L>`, and the ceiling is capped at twice the limit. A host with no limit record has no L, so it can't be decided whether a retest can be approved there.
- **A6, GO-023.8 (bullet 1 against bullet 2):** bullet 1 covers goals "approved before this item merged". Bullet 2 covers goals "drafted after this item merged". A goal drafted before the merge and approved after it falls in neither. It's unclear whether it needs a `DEPS.json` or can be a serial chain.
- **A7, GO-023.9 against the constraint "Test the boundaries before adding item IDs":** the report is allowed because "GO-017 records the three boundary tests passing on 2026-09-29". The plan text has no *Boundary tests* section and no GO-017 record. The constraint covers new "metrics work", which includes a new measurement report. Whether this one is allowed can't be decided from the plan.
