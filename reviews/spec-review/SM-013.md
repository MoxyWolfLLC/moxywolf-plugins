# Spec review: DESIGN.md SM-013

_2026-11-24T17:34:54+00:00 · claude-sonnet-5-5 with claude-fable-5-2 advisor (1 calls)_

I found no contradictions. Every pair I checked can be satisfied together, so the list is empty. Several requirements can't be decided from the plan's text, so I list those as ambiguities.

- **SM-013.1 and SM-013.7 (what is exempt).** SM-013.1 exempts "changelog and version-history text" in general. SM-013.7 exempts only `plugin.json` changelog clauses, README Version History sections and "the test files that name them on purpose". A history entry in `CHANGELOG.md`, `GOVERNANCE.md` or `SKILL.md` that names Taskade passes SM-013.1 but fails SM-013.7. SM-013.1 also says "no file", while SM-013.7 allows test files that name the strings. The plan doesn't say which exemption set is authoritative.
- **SM-013.6 and SM-013.7 (path coverage).** SM-013.6 bars any `/Users/doriancougias` path. SM-013.7 only scans for `/Users/<name>/Library/CloudStorage/GoogleDrive-`. A non-Drive `/Users/doriancougias` path would break SM-013.6 and go undetected. The plan doesn't say whether SM-013.7 must cover it.
- **SM-013.6 (fallback and its trigger).** The "mounted folder" fallback is never defined, and it can't be an absolute `/Users` path without breaking SM-013.7. The "Links introduced" paragraph triggers the fallback when project-init "isn't" installed. SM-013.6 triggers it when `drive_roots.py` "can't run". These are different conditions.
- **SM-013.3 (mixed story points).** Story points are used "where the field is set, otherwise counts by issue, and the deck says which". The plan doesn't say what happens in a sprint where only some issues have points. It also doesn't say whether the choice is made per issue or per sprint.
- **SM-013.2 and SM-013.7 (path form).** SM-013.2 doesn't say whether the `GitHub/Projects` targets are absolute or relative. "Each target file exists today" doesn't say where that is checked or by what. An absolute path would hit SM-013.7's scan.
- **SM-013.8 and "The pre-merge gate is GitHub's" (CODEOWNERS path).** Making `scripts/run_all_tests.py` report a count of what it examined may require editing it. That file is a `CODEOWNERS` path, so the change would need Dorian's approving review. The plan doesn't say whether the change is intended or whether the count can come from the new test instead.
- **SM-013.8 and "One release path, checked by code" (post-merge mirror).** The post-merge mirror of this document isn't a condition a script checks. The plan doesn't say which status move, if any, it gates.
- **SM-013.4 (existing state).** The plan doesn't say how existing state that still carries `taskadePath` is handled. It doesn't say whether a migration or a fallback read is needed, and SM-013.7 would flag any fallback that kept the old key's name.
