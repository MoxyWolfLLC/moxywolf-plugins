# Spec review: DESIGN.md XE-045

_2026-11-17T18:22:36+00:00 · claude-sonnet-5-5 with claude-fable-5-2 advisor (1 calls)_

I found no pair of requirements that cannot both be satisfied, so the contradictions list is empty. I found six ambiguities in XE-045. I did not cite XE-012, XE-029 or CI-002, because their text is not in the plan.

- **XE-045.4 and XE-045.7 (what "absent" means):** XE-045.4 gives `absent` to a pre-pass that ran but whose criteria hash didn't match, or that named a different set of repositories. XE-045.7 calls `absent` "skipped" and excludes it from the count. A builder who ran a pre-pass and then rewrote the criteria is excluded from the drop count. The plan doesn't say whether that is intended.
- **XE-045.7 and XE-045.4 (where the repository comes from):** XE-045.7 counts a review "under the first repository in its packet, as its `opened` marker names it". It also says the count is read from the `state.json` files. XE-045.4 says `open` writes only one field, `goldfish`, to `state.json`. The plan doesn't say whether `state.json` carries the repository identity or the count must join against the record.
- **XE-045.4 alone (precedence):** a first matching entry may name a different set of repositories and also a different head in a shared repository. The plan doesn't say whether `ran_earlier` or `absent` wins.
- **XE-045 Links and XE-045.4 (a shared record):** an upstream and a fork with the same item ids and base share one record, and only entries after the record's last `opened` marker count. A fork's `open` between an upstream pre-pass and the upstream `open` would push that pre-pass out of the window. The plan doesn't say whether "last marker" is per repository.
- **XE-045.6 and XE-045.7 (reaching ten):** skipping is allowed and skipped reviews don't count, so ten counted reviews may never be reached. The plan doesn't say whether "ten" means the first ten or any ten. It also doesn't say what decides the item if it never gets there.
- **XE-045.2 alone (partial replies):** "returns no criteria list" doesn't say whether a reply covering only some criteria counts as answered (exit 0, entry appended) or as a failure.
