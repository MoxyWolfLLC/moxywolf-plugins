**Ambiguities**
- **GA-013.7 against GA-013.3 and the pre-merge gate constraint.** GA-013.7 says "A light-lane change never touches an `owned` path (XE-049.7)". GA-013.3 puts only four paths in the closed lane, and the intro says the table puts `hooks/`, `goals/` and the gate scripts in none. The plan doesn't say whether a change touching only `hooks/` can classify as `light`. If it can, it would merge with no review while the ruleset demands Dorian's approving review. The plan must say how `owned` paths are excluded from `light`.
- **GA-013.9 against GA-013.10.** Criterion 10 says the watcher "never merges", yet criterion 9 has it merge `main` into the branch. The plan doesn't say whether "merges" in criterion 10 means only the pull request merge.
- **GA-013.9, internal.** The text reads "isn't the watcher's own" and then "comments by `moxywolf-agent` never trigger it". The plan doesn't say whether the bot's own cross-vendor review comments count as the watcher's own.
- **GA-013.4, GA-013.1 and GA-013.3.** A repository table "replaces the default whole", but only closed *paths* are checked, and criterion 3 also adds two *effects*. The plan doesn't say whether a repository table must also carry `owned` and the two new effects, so CKI's required contents are unclear.
- **GA-013.6 against GA-013.7 and GA-013.14.** GA-013.6 is a numbered criterion, but the text says the item can be done before it and the first live post is "not a criterion". The plan doesn't say whether it gates `done`.
- **Boundary-tests constraint against GA-013.1, GA-013.3 and GA-013.5.** The constraint bars new vocabulary until the boundary tests run. GA-013 adds the effects `adds_symlink` and `changes_submodule`, the `mode` values and `would_lane`. The plan doesn't say whether any of these count as barred vocabulary or only as fields on the item's own record.
- **GA-013 intro and GA-013.7.** After a push the new head has no status until the next `open` or light-lane release, and nothing in the plan moves a `pending` status. A watcher push therefore leaves a head with no lane status, and the plan doesn't say whether that is acceptable.
