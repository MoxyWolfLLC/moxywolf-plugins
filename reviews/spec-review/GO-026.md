# Spec review: DESIGN.md GO-026

_2026-11-24T00:00:55+00:00 · claude-sonnet-5-5 with claude-fable-5-2 advisor (1 calls)_

I found no contradictions in GO-026 that I could defend, and I found five ambiguities. I dropped two of the advisor's contradiction candidates.

- **GO-026.1 against GO-026.3 (the log):** these do not conflict. A failed `install` can name a log that holds only start lines.
- **Constraint "stores … nothing" against the log file:** the log is not transcript-derived data, so the named exception covers it.

The ambiguities:

- **A1, which port `status` checks:** `AGENT_FLOW_PORT` is set at `install` time, and GO-026.2 does not say which port `status` probes. A later `status` run in a shell without the variable could probe 61469 and report a viewer that is not running, or the reverse.
- **A2, the login shell against `PATH` in the plist:** GO-026.1 says `npx` comes from a login shell. GO-026.6 tests that the plist names `npx`'s folder on `PATH`. The text does not say whether the plist launches through a login shell or sets `PATH` itself.
- **A3, how 127.0.0.1-only binding is guaranteed:** GO-026.3 says the viewer binds 127.0.0.1 only "as `swarm.py`'s does". The plist command line in GO-026.1 has no host flag. GO-026.4 pins only the package string, not the arguments, so nothing says the package binds loopback by default.
- **A4, the always-on port against a goal's own viewer:** GO-026.1 fixes the default port at 61469. GO-025's viewer port is not stated in the plan, so a clash cannot be ruled out.
- **A5, CI-002:** GO-026.7 cites it for the version moves, but the plan does not define it.
