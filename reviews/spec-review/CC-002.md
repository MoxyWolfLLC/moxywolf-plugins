I called the advisor and checked each of its suggestions against the plan text. I still found no contradictions. Each suggested pair can be satisfied, and the text doesn't settle which way it goes, so I recorded all of them as ambiguities (A6–A10). A1–A5 are unchanged.

- **Retiring a proposal case (A6):** CC-002.7 says the manifest states "a proposal case expires 12 months after publication". It also says `retire` sets "retirement plus 12 months", and the plan never says whether `retire` accepts a proposal case. If it does, the ledger date and the manifest rule disagree. If it doesn't, nothing conflicts. The text doesn't decide, so this is an ambiguity.
- **Window between folder deletion and `delete-record` (A7):** CC-002.7 has the person delete the folder first and then run `delete-record`. CC-002.8 expects a missing folder only for a `deleted` case or one with a pending `delete-record`. In the gap, `verify` fails, and `publish`, `apply` and `status` run it first. The plan doesn't say whether that failure blocks them. If it does, `apply` is stuck until the person runs `delete-record`.
- **Pending `exclude` (A8):** CC-002.7 treats a pending `exclude` as an exclusion "at once" for every reader. It also says a case holds exactly one ledger state. Neither requirement says whether `due` and `verify` count the pending request.
- **`run_all_tests.py` (A9):** CC-002.12 says it "names `test_council_cases.py`". The pre-merge gate constraint makes `run_all_tests.py` a `CODEOWNERS` path. The plan doesn't say whether the item edits it or discovery picks the test up automatically.
- **`/deliberate` running `apply` (A10):** CC-002.5 has `/deliberate` run `apply` on the writer. CC-002.8 has `apply` run `verify` first, and a conflict copy stops `verify`. The plan doesn't say whether `/deliberate` itself fails or just reports.
