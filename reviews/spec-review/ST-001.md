I found no definite contradictions in ST-001. There are four ambiguities, and the first two matter most.

- **Self-test vs. "never gate" (ST-001.4, ST-001.7):** ST-001.4 says lint "exit status" never gates merge, but `run_all_tests.py` must require `ste-lint.py --selftest` to pass. A failing self-test turns the required `tests` check red and blocks the merge. If a self-test run counts as a "lint-run exit status", the two sentences conflict. The text doesn't say which reading applies.
- **Silence on Dorian's review (ST-001.4, ST-001.7):** `run_all_tests.py` is a `CODEOWNERS` path, so the ruleset requires Dorian's approving review at the head. The item never says so. It sits beside "Every other change merges with no human approval" and "The agent merges on a clean review", so the review path for this item is unclear.
- **Dorian's voice (ST-001.3):** The in-scope list includes DESIGN.md items and amendments and goal briefs. The exclusion covers "anything written in Dorian's voice". Those documents record his words, so the text can't settle which rule governs them.
- **Version lines (ST-001.6):** The diff must show "the new entry and the version line only". The new entry carries its own `0.1.0` version, and the top-level version moves too, so there are two version lines.

I left out the "three places" vs. "three hunks" wording in ST-001.3 and the `LICENSE` path mapping in ST-001.2. These are minor and don't change whether the item can be satisfied. I also saw no conflict with the boundary-tests rule or the GA-scope limit. CI-001, CI-002 and the packet are referenced but not defined in this plan, so I did not cite them as requirements.
