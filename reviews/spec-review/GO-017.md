I checked the advisor's fifth item and I'm filing it as an ambiguity, not a contradiction. The text doesn't force two requirements to clash in a reachable scenario, but it also doesn't settle the case. I'm filing the sixth as an ambiguity too. The first four are unchanged.

**Fifth item: clean review with coverage not `checked`.**
- *Coverage is mandatory* says such a review passes `record-release` only if the owner's exception is recorded at that head before the merge. It also says "The agent never merges on coverage that isn't `checked`, so the owner makes that merge."
- GO-017.6 says the item merge "still goes through `goal_run.py may ... merge`, which needs a clean cross-vendor review with coverage `checked`." That path can't carry the exception merge.
- GO-017.6 `merge-gate` passes only "when the item is reviewed at the tested head" and "the target is still where the coordinator's last merge left it". The plan doesn't say whether a review with an exception counts as "reviewed" for the gate.
- An owner-made merge also moves the target outside the coordinator's own merges. The plan doesn't say how `merged` (GO-017.7) learns of it.
- `refresh` (GO-017.6) drops the old review. The exception is recorded "at that head", so it presumably lapses too.
- Because the gate wording can be read either way, a coverage-unchecked swarm item may be unmergeable. I'm leaving it as an ambiguity.

**Sixth item: reservation charge.** GO-017.3 charges a tokens-only worker "its reservation". It also says "so no dollar figure is recorded that nobody measured". Charging the reservation does record a dollar figure that nobody measured, though it is flagged `estimated: true`. The plan doesn't say whether the flagged charge satisfies the sentence.
