# Spec review: DESIGN.md XE-049

_2026-11-24T06:26:24+00:00 · claude-sonnet-5-5 with claude-fable-5-2 advisor (1 calls)_

I checked both contradiction candidates and rejected them, so `contradictions` is empty and there are eleven ambiguities. Every finding involves XE-049, so none is a constraints-only conflict.

**Candidates rejected**
- **XE-049.11 against "Preserve cross-tool review, pinned commits, bounded review rounds, and recursion refusal".** Uncounted post-sync rounds are still finite, because each is triggered by a sibling merge in a finite batch. The bound is therefore not violated outright, and what remains is the question A2 raises.
- **XE-049.7 against the same constraint.** The constraint preserves cross-tool review as a mechanism, and `light` is an explicit, Dorian-approved exemption. The plan's amendment list names the *One release path* and *The agent merges on a clean review* bullets but not this one. That makes it a question about what "Preserve" allows, so it goes in as A6.

**Ambiguities**
- **A1:** XE-049.11 and XE-049.7. The plan doesn't say what the sync "delta" is measured over, or how sibling Amendments lines are handled, given that the overlap test ignores them but criterion 7 says they are never `light`.
- **A2:** XE-049.11, XE-049.1 and the "bounded review rounds" constraint. Post-sync fix-verification rounds are uncounted, and the plan states no other limit on how many a pull request can need.
- **A3:** XE-049.7 and *The approval ledger is attention, not containment*. "Check ledger" is undefined, so it isn't clear whether using it in place of review claims that a ledger stops something.
- **A4:** XE-049.4 and XE-049.5. A goal item's done line needs the goal's pull request number, which doesn't exist while items commit straight to `goal/<id>`.
- **A5:** XE-049.10, XE-049.11, the Goal, and *Test the boundaries before adding item IDs*. It is unclear whether width from `DEPS.json` and the parallel builders are barred graph work or parallel execution that arrives before governance is done. XE-049's waiver covers only two words and one status form.
- **A6:** XE-049.7 and the first constraint, "Preserve cross-tool review, pinned commits, bounded review rounds, and recursion refusal". It is unclear whether "Preserve" permits a lane with no cross-vendor review. XE-049.9's amendment list doesn't name this bullet.
- **A7:** XE-049.11 and XE-049.1. In a post-sync fix-verification round, the plan doesn't say what "the fix's diff" is. It also doesn't say whether blockers in code merged in from `main` are demoted as `new_in_verification`.
- **A8:** XE-049.7 (existing `test_*.py`) and XE-049.7 ("green `tests` … stand in"). The check that replaces review can itself be edited in the same unreviewed lane.
- **A9:** XE-049.10 and XE-049.15. It is unclear whether "capped at 10" binds only the default width or also a brief's `max_workers`.
- **A10:** XE-049.4 and XE-049.7. A `light` change has no review, so "the last commit before review" has no meaning for it.
- **A11:** XE-049.2 and XE-049.4. A fix commit after round 1 means the done-line commit is no longer the last one before review. The plan doesn't say whether the line must be re-set or re-verified.
