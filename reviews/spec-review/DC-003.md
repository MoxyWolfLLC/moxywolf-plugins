# Spec review: DESIGN.md DC-003

_2026-11-20T22:59:26+00:00 · claude-sonnet-5-5 with claude-fable-5-2 advisor (1 calls)_

I found no contradictions in DC-003. There are six ambiguities, and the first four are unchanged from my earlier reply. The advisor added two, which I checked against the plan's text, and both hold up.

- **DC-003 criterion 9 and criterion 10(a):** Criterion 9 says `limit_usd` is no higher than the key's Vercel budget and that 10(a) checks it. But 10(a) only checks that the key shows a $1 limit. It doesn't compare that to the budget file's `limit_usd`, and `init` can't check it offline.
- **DC-003 criterion 7 and criterion 4:** The plan doesn't give `ask`'s exit code when a voice settles as `kept_unknown`, or when a voice is refused as `no_price` or `unbounded_fee` while other voices are sent. Only `ceiling_exceeded` (exit 5) and whole-call refusals (exit 4) have codes.
- **DC-003 criterion 8 and criterion 7:** Criterion 8 doesn't say how "a reservation whose process is gone" is detected, for example pid reuse or a slow process that is still alive. It also doesn't say what a later settle does to a reservation that `recover` already marked `kept_unknown`.
- **DC-003 criterion 3 and criterion 6:** Criterion 3 reads the "decider ledger" at call time, but criterion 6's test uses a different `GSTACK_PEER_REVIEW_DIR` per process. The plan doesn't say which ledger supplies the ceilings.
- **DC-003 criterion 3 and criterion 7:** Criterion 3 reads a ledger row's `budget_state`, but criterion 7 and the Links list declare only `reserved_usd` and `settled_usd` on the ledger line. The `state` field is declared on the budget file, not the ledger. So it isn't clear whether `budget_state` is a ledger field the item writes. If it is, the plan doesn't say what values it takes or how it relates to the budget file's `state`.
- **DC-003 criterion 3 and criterion 4:** Criterion 3 skips "a row refused under criterion 4 (`no_price`, `unbounded_fee:<name>`)". But `no_price` is defined in criterion 3, and criterion 4 defines only `unbounded_fee` and `pricing_unavailable`. The plan also doesn't say which ledger field records a refused voice, so a reader can't tell which rows to skip.
