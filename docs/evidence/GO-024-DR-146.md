Dorian ruled out switching to CLI workers or paying for more probes for this.

# DR-146: The swarm recommends up to 30 workers; the default stays 3

**Date**: 2026-11-21
**Project**: Moxywolf Plugins (`plugins/gstack-execution`, GO-024)
**Decision Maker**: Dorian
**Status**: accepted. Dorian approved this wording on 2026-11-21 ("Approve"). Item GO-024 is in pull request #370 (`build/GO-024-swarm-width-30`); the merge commit is recorded below once it exists.

## What this supersedes

[[Projects/Moxywolf Plugins/06-Engineering/DR-142-parallel-builds-through-a-bounded-swarm-2026-11-19|DR-142]] says, under **Shape**: "Up to 3 workers and 1 coordinator (`swarm.py`)." This record supersedes that sentence and nothing else in DR-142.

GO-023 already lets an approved ordinary goal opt in to a wider run with an explicit `max_workers` and imposes no software maximum, so the code needed no change. This record sets the policy that sits on top of it.

## Decision

- **Default stays 3.** `DEFAULT_WORKERS` is unchanged. An omitted `max_workers` means 3, and a goal with no `DEPS.json` still runs serially.
- **Up to 30 is the recommended width.** An ordinary goal whose plan has enough independent work may set an explicit `max_workers` up to 30, and `/gstack-goal-new` recommends that figure. The runner itself imposes no maximum (GO-023).
- **Two limits still bind.** A goal with a `## Hard cap` section is refused above 3. The host ceiling stays downward-only and holds a run at its recorded limit at any width.

## What stays as DR-142 set it

Opt-in through `DEPS.json`. One writer under a blocking flock. Integration in dependency order. The merge gate refuses a candidate not built on the moved target until it is refreshed and re-reviewed. Exact-head cross-vendor review. The per-item review cap. CODEOWNERS. Protected review and security work stays out of the swarm. A dispatch budget, not a spend cap.
